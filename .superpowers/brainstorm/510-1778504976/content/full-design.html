Schema 2 — Fahrer Login & Onboarding

Schritt-für-Schritt Flow

1
IMD legt Fahrer an
Im Dashboard: Name, E-Mail, Fuhrpark auswählen → Speichern.
System erzeugt invite_token (32 Bytes, hex) + invite_expires_at (+72h). aktiv = false.
POST /api/fahrer fahrer INSERT Auth: IMD Admin
2
Einladungs-E-Mail automatisch versendet
Resend sendet E-Mail an Fahrer mit Link:
/fahrer/aktivieren?token=<hex> — 72 Stunden gültig, einmalig verwendbar.
Resend E-Mail Token: 72h · einmalig
3
Fahrer setzt Passwort (Aktivierung)
Öffnet Link → Seite zeigt Formular: "Passwort wählen".
Server prüft: Token gültig? Nicht abgelaufen? → Passwort mit crypto.scrypt hashen → aktiv = true, Token löschen → Session erstellt → Weiterleitung zu /schaden.
GET /fahrer/aktivieren POST /api/fahrer/aktivieren fahrer UPDATE
4
Login (E-Mail + Passwort)
Seite /fahrer/login → E-Mail + Passwort eingeben.
Session: req.session.fahrerId + req.session.fuhrparkId → Weiterleitung zu /schaden.
Formular wird automatisch vorausgefüllt (Name, E-Mail, Fuhrpark).
GET /fahrer/login POST /api/fahrer/login Session: fahrerId
!
Passwort vergessen → Magic Link Reset
Fahrer gibt E-Mail ein → System erzeugt reset_token (15 Min gültig) → E-Mail mit Link → Fahrer klickt → neues Passwort setzen. Kein klassischer "Passwort vergessen"-Flow nötig.
POST /api/fahrer/reset-anfragen POST /api/fahrer/reset Resend E-Mail
