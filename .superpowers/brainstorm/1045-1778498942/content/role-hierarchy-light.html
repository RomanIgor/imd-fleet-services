Rollenkonzept — Welche Variante passt zu IMD?

Wer soll Zugriff auf das System haben? Wähle den Ansatz, der am besten passt.

A

2-Ebenen (aktuell / vereinfacht)

IMD Admin → Fahrer

IMD legt jeden Fahrer manuell an. Kein Zwischenmanager. Fuhrpark ist nur ein Dateneintrag (kein Login).

✓ Einfach zu implementieren ⚠ Skaliert nicht ✗ IMD muss alles manuell pflegen
B

3-Ebenen — B2B SaaS Standard ★ Empfohlen

IMD Admin → Fuhrparkmanager → Fahrer

Jeder Fuhrpark bekommt einen (oder mehrere) Manager mit eigenem Login. Der Manager verwaltet seine eigenen Fahrer selbst — IMD muss sich nicht um jeden Einzelnen kümmern.

Was kann der Fuhrparkmanager?
✓ Fahrer einladen & deaktivieren (nur eigener Fuhrpark) ✓ Alle Schadensmeldungen seines Fuhrparks sehen ✓ Fahrzeuge verwalten (später) ✓ Statistiken für seinen Fuhrpark ✗ Kein Zugriff auf andere Fuhrparks ✗ Kein Zugriff auf IMD-Admin-Bereich
✓ Skaliert auf 100+ Fuhrparks ✓ Echter B2B SaaS Standard ✓ Weniger Arbeit für IMD ⚠ Mehr Implementierungsaufwand
C

3-Ebenen + Sub-Rollen (komplex)

IMD Admin → Fuhrparkmanager (Admin/Viewer) → Fahrer

Wie B, aber Fuhrparkmanager hat zwei Unter-Rollen: "Admin" (darf Fahrer anlegen) und "Viewer" (nur lesen). Sinnvoll wenn Fuhrparks große interne Teams haben.

✓ Maximale Flexibilität ✗ Deutlich komplexer ✗ Für Phase 1 zu früh
Empfehlung: Option B ist der richtige Weg für ein B2B SaaS. Ohne Fuhrparkmanager muss IMD jeden einzelnen Fahrer bei 10, 20, 50 Fuhrparks manuell anlegen — das skaliert nicht. Mit Option B delegiert IMD die tägliche Verwaltung an den jeweiligen Fuhrpark.
