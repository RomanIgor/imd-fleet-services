Schema 2
Fahrer-Login & Account-Erstellung — Ablauf
A Warum Einladungsbasiert?
  • Kein Fahrer kann sich ohne IMD-Freigabe registrieren
  • Jeder Account ist einem verifizierten Fuhrpark zugeordnet
  • Kein Spam / unerwünschte Zugänge möglich
  • IMD behält volle Kontrolle über alle Zugänge
B Zwei Einstiegswege
  • IMD legt Fahrer direkt im Admin-Dashboard an
  • Fuhrpark-Kontakt schickt eine Liste an IMD → Massenimport
  • System sendet automatisch den Einladungslink per E-Mail
  • Link ist 72 Stunden gültig, einmalig verwendbar
Schritt-für-Schritt Ablauf
1
IMD legt Fahrer an
Im IMD-Dashboard: Name, E-Mail und Fuhrpark-Zuordnung eingeben.
System erstellt einen einmaligen invite_token und speichert aktiv = false.
POST /api/fahrer DB: fahrer INSERT
2
Einladungs-E-Mail wird automatisch versendet
System sendet eine E-Mail an den Fahrer via Resend:
„Sie wurden von [Fuhrpark GmbH] eingeladen. Klicken Sie hier, um Ihr Konto zu aktivieren."
Link enthält den Token: /fahrer/aktivieren?token=abc123…
E-Mail via Resend Token: 72h gültig
3
Fahrer aktiviert Konto & setzt Passwort
Fahrer öffnet Link → Seite /fahrer/aktivieren → gibt Passwort ein.
System prüft Token-Gültigkeit, setzt Passwort (bcrypt), markiert aktiv = true, löscht Token.
GET /fahrer/aktivieren?token=… DB: fahrer UPDATE
4
Fahrer loggt sich ein
Seite: /fahrer/login — E-Mail + Passwort.
Bei Erfolg: Session wird erstellt (req.session.fahrerId), Weiterleitung zu /schaden.
Das Formular wird mit den Fahrerdaten vorausgefüllt (Name, E-Mail, Fuhrpark).
POST /api/fahrer/login Session: fahrerId
✓
Fahrer reicht Schadenmeldung ein
Formular ist vorausgefüllt. Fahrer ergänzt Schaden-Details und sendet ab.
Meldung wird fahrer_id und fuhrpark_id zugeordnet.
IMD und Fahrer erhalten Bestätigungs-E-Mail mit Schadennummer.
POST /api/schaden DB: schaeden INSERT E-Mail → IMD + Fahrer

Schema 3
Umsetzungsstand & Realisierbarkeit als SaaS
Ehrliche Standortbestimmung

Die Plattform befindet sich aktuell bei ca. 8–10 % der Gesamtspezifikation. Das klingt wenig — ist aber ein solides, produktionsreifes Fundament. Das Schadenmanagement-Modul ist bereits voll funktionsfähig und für erste Kunden lieferbar. Die Architektur (Node.js · PostgreSQL · REST API · EU-Hosting) ist korrekt gewählt und skalierbar auf alle weiteren Module.
